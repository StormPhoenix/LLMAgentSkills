# 爆款改写

## 执行回执（硬规则）

只要本轮因为 `skill` / `技能` 指名，或因为关键词命中而进入本技能，第一行先写：
`已走技能：爆款改写`

---

## Step 0: 读取用户画像

**需要的信息**：行业、目标客群、核心产品/服务、说话风格、转化动作（加微信/到店/下单等）。

从系统记忆、用户画像、对话上下文中提取以上信息。已有的直接用，缺的才问。

如果完全没有画像信息且用户选了"纯改写"模式，可以跳过——纯改写不需要业务信息。
如果用户选了"业务钩子"模式但没有画像，必须快速问一句：

```
你是做什么行业的？想让观众做什么动作？（比如"做餐饮的，想让人加微信"）
```

---

## Step 1: 接收文案 + 爆款基因分析

用户发来一段文案后，先做**爆款基因分析**（3句话以内，不废话）：

```
爆款基因：
- 为什么火：{一句话，如"击中了老板被甲方压价的共鸣"}
- 情绪钩子：{一句话，如"开头用反常识数字制造悬念"}
- 结构节奏：{一句话，如"先铺痛点→翻转→给解法→收口"}
```

分析完直接进入 Step 2，不等用户确认。

---

## Step 2: 选模式

分析完后紧接着问：

```
你要哪种改写？

1. 纯改写（去重换说法，不加业务内容）→ 出 2 条
2. 改写+业务钩子（改写后自然植入你的业务）→ 出 2 条
3. 全都要 → 出 4 条
```

如果用户在发文案时已经说了（如"帮我纯改一下"），直接跳过不问。

**默认模式**：如果用户什么都没说直接发了文案，默认走 1（纯改写）。

---

## Step 3: 执行改写

### 改写前内部拆解（不输出给用户）

先把原文拆成功能模块：
- **钩子**（前 5 秒 / 前 2-3 句）
- **展开**（故事/案例/观点铺设）
- **转折**（情绪拐点/认知翻转）
- **证据**（数据/细节/行业真相）
- **收口**（金句/行动引导/人设收尾）

标记每个模块的情绪走向（好奇→共鸣→愤怒→释然等），改写时严格保持同样的情绪曲线。

---

### 模式 1：纯改写（选 1 时出 V1 + V2）

#### V1：换皮版

**规则**：
- 前 5 秒（前 2-3 句）**一个字不改** — 这是原爆款验证过的钩子，不动
- 从第 4 句开始做**彻底的同义词替换**：每句话都换一种说法，但意思完全一样
- 保持原文长度（字数浮动不超过 10%）
- 保持原文的段落结构和推进顺序不动
- 目标：查重率归零，但读起来传递的信息完全一样

#### V2：狠劲版

**规则**：
- 前 5 秒同样不改
- 在原文基础上**加强情绪颗粒度**：
  - 去掉啰嗦的连接词（"然后""接下来""所以说"）
  - 换成更短促有力的表达
  - 加入口语化的情绪词（"离谱""搞毛""有毛病""太扯了"）
- 让情绪更直接、更像在跟朋友吐槽
- 可以比原文稍短（删赘词），但核心信息一个不能少

---

### 模式 2：改写+业务钩子（选 2 时出 V3 + V4）

#### V3：翻转版（结尾植入业务）

**规则**：
- **主体（智能改写）**：用全新的语言重写原文故事/观点，但**严格保留**原文的起承转合和情绪节奏。不是逐句替换，是用自己的话重新讲同一个故事
- **结尾（业务翻转）**：在情绪最高点，自然转折关联到用户的业务
- 转折要自然，不能硬接。好的转折像"你看，其实这个道理放到{用户行业}也一样..."，差的转折像"说到这个，我们公司刚好..."
- 结尾的行动引导用用户画像里的转化动作（加微信/评论区/到店等）

#### V4：圈人版（首尾植入业务）

**规则**：
- **开头（圈人）**：在原文钩子前面加一句极短的圈人语——"做{用户行业}的老板听好了" / "{用户行业}的注意了"
- **主体（智能改写）**：使用"倒叙"或"换一种说法"来重述原文核心观点，规避平台查重，但保留原文的节奏感和"劲"
- **结尾（行动指令）**：加一句极短的行动引导，用用户画像里的转化动作

---

### 模式 3：全都要（选 3 时出 V1 + V2 + V3 + V4）

四个版本全部输出。

---

## Step 4: 输出格式

严格按以下格式输出，**每条文案必须在代码块里**（方便一键复制念稿）：

```
💡 爆款基因分析

- 为什么火：{一句话}
- 情绪钩子：{一句话}
- 结构节奏：{一句话}

---

{如果是纯改写}
📝 纯改写（2条）

### V1：换皮版
{完整文案}

### V2：狠劲版
{完整文案}

{如果是业务钩子}
🎯 改写+业务钩子（2条）

### V3：翻转版
{完整文案}

### V4：圈人版
{完整文案}
```

输出完毕后，追加一句：
```
直接复制念稿就能拍。要调整哪条说一声。
```

## 禁止操作

**严禁** 改动前 5 秒（前 2-3 句）的钩子——这是原爆款验证过的黄金开头，动了等于自杀。
**严禁** 改变原文的核心观点和立场——换说法不换意思，这是铁律。
**严禁** 在纯改写模式（V1/V2）里植入任何业务内容——用户选了纯改写就是不要广告。
**严禁** 在业务钩子版（V3/V4）里硬接广告——转折必须自然，不能"说到这个我们公司刚好..."。
**严禁** 输出超出原文 30% 长度的改写——爆款的节奏感靠篇幅控制，不能注水。
**严禁** 使用 AI 味表达——"在当今社会""值得注意的是""随着时代发展"一律不用。
**严禁** 编造原文没有的数据、案例、故事——你是改写不是创作。

## 通用规则

### 零配置，即插即用
- 不需要 API Key，不依赖任何外部服务
- 行业自适应，任何行业都能用

### 受众自动迁移
- 如果原文是写给某个特定人群的（如宝妈、学生、打工人），改写时自动迁移到用户画像里的目标客群
- 迁移的是**逻辑和情绪**，不是硬改名词。比如原文说"宝妈半夜喂奶的崩溃"，迁移到老板就是"老板半夜对账的崩溃"，保持同样的情绪强度

### 异常处理
- 用户发的不是文案（是链接/截图/语音）→ 提示："把文案文字发给我就行，我来改写"
- 原文太短（不到 100 字）→ 正常改写，但提示"原文偏短，改写空间有限，建议找 300 字以上的爆款效果更好"
- 原文是硬广/促销文案 → 提示"这条是广告不是内容，改写价值不大。建议找有故事、有观点的爆款来改"

## 保存到本地内容库（主动追问）

### 必做：文案展示完后立刻追问保存

不管用户有没有提保存，**每次输出文案后都要主动问一次**：

```
---

📁 **要把这篇保存到你的本地内容库吗？**

  会保存到：桌面/我的内容库（勿动）/05-爆款改写/{{日期}}-{{关键信息}}.md

  1. 保存（推荐）
  2. 不用
```

**规则**：
- 用户选"1" → 先用 `get_path` 获取桌面路径，再用 `write_text_file` 工具保存，确认后回复"已保存到 {{完整路径}}"
- 用户选"2" → 结束
- 用户模糊回答（"好""嗯""可以"）→ 按"1"处理
- **严禁** 跳过这一问
- **严禁** 只在对话里说"已保存"但实际没写文件

### 保存路径

`{桌面}/我的内容库（勿动）/05-爆款改写/{{YYYY-MM-DD}}-{{关键信息}}.md`

同一天重复生成加时分：`{{YYYY-MM-DD-HH:MM}}-{{关键信息}}.md`

### 保存前检查

- 先用 `get_path` 获取桌面路径，拼接 `我的内容库（勿动）/` 检查是否存在
  - 不存在 → 告诉用户"你还没搭建内容库，先跑'内容库搭建'skill"，**停止保存**
- 检查 `05-爆款改写/` 子文件夹是否存在
  - 不存在 → 用 `create_directory` 创建

### 文件内容格式

```markdown
# {{标题}}

> 生成时间：{{YYYY-MM-DD HH:MM}}
> Skill：爆款改写
> {{其他元信息}}

---

{{文案正文}}
```

### 严禁事项

1. **严禁** 跳过"主动追问"这一步
2. **严禁** 只说"已保存"但实际没写文件
3. **严禁** 保存到错误的子文件夹（必须是 05-爆款改写）
4. **严禁** 保存到没有"（勿动）"后缀的路径
5. **严禁** 硬编码路径（如 `C:\Users\...`），必须通过 `get_path` 获取
