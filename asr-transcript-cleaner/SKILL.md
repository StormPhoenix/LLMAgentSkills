# ASR 转录文本清洗（asr-transcript-cleaner）

> **本 Skill 是"指引 + 脚本型"。** 内置 `asr-cleaner.cjs` 确定性脚本，
> 通过工具 `clean_asr` 调用。脚本仅做机械规则操作（去空格、插标点、换行、输出 MD 格式、校验），
> 不"理解"文本，因此不会丢失任何字符。

## 何时激活此 Skill

满足以下任一条件时激活：

- 用户提到清洗 / 格式化 ASR 转录文本
- 用户说"字间有空格""去掉空格加标点""转录文本格式化"
- 用户需要给 `.txt` 转录文件批量加标点
- 用户希望验证已有清洗结果的完整性

不要激活的场景：

- 用户要做的是**内容总结 / 知识提取**（那是 `live-knowledge-distiller` 的事）
- 用户要修改已有标点 / 重新润色文本（本 Skill 只处理无标点的原始 ASR 文本）

## 核心约束（Hard Constraints）

清洗的唯一目标是**提升可读性，同时 100% 保留原文内容**。不允许的操作：

- ❌ 总结、改写、纠错、润色
- ❌ 删除任何非空格字符
- ❌ 添加解释性文字
- ❌ 在校验通过前替换原始文件

允许的操作（仅此四项）：

1. 插入标点：`， 。 ？ ！ ； ： 、 " " （ ）`
2. 插入段落换行
3. 删除 ASR 字间空格和制表符
4. 保持所有原始非空格字符的顺序不变

## 工具调用

### clean_asr

```javascript
clean_asr({
  sourcePath: "G:/Workspace/RawResourceBase/做多中国的好人豆子/直播转录/26_07_13-xxx_BVxxx.txt",
  outputPath: "G:/Workspace/RawResourceBase/做多中国的好人豆子/直播转录标点测试/26_07_13-xxx_BVxxx.md"
})
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `sourcePath` | string | ✅ | 源文件或目录绝对路径（文件→单文件，目录→批量） |
| `outputPath` | string | ✅ | 输出文件或目录绝对路径 |
| `checkOnly` | boolean | ❌ | 默认 `false`，仅校验不重新清洗 |

**单文件模式**（`sourcePath` 是文件）：
- 生成 `<stem>.md`（清洗结果，含一级标题）和 `<stem>.check.md`（校验报告）

**批量模式**（`sourcePath` 是目录）：
- 处理目录下所有 `.txt` 文件，每个生成 `.md` 和 `.check.md`
- 返回汇总结果（通过数 / 失败数 / 失败文件列表）

**仅校验模式**（`checkOnly: true`）：
- 不重新清洗，对已有的 `.md` 做无损校验

## 标点插入规则

脚本基于口语模式保守插入标点，规则包括：

**逗号**（在特定词语前/后插入）：
- 前：`但是`、`然后`、`所以说`、`实际上`、`我觉得`、`说实话`、`也就是说`、`当然`、`不过`、`反正` 等
- 后：`然后`、`那么`、`所以说`、`实际上`、`当然`、`总之`、`好的`、`好吧` 等

**句号**：`完了`、`结束了`、`就这样`、`就是这样`、`没办法`、`再见`、`拜拜` 等

**感叹号**：`我操`、`我靠`、`太恐怖了`、`太逆天了`、`受不了了`、`死定了` 等

**问号**：`是不是`、`对不对`、`有没有`、`能不能`、`为什么`、`怎么办`、`吗` 等

规则按词语长度从长到短排序匹配，避免短词误拆长词。

## 换行规则

- 每行最多 100 个原始字符（不含插入的标点）
- 在句末标点（`。` `？` `！`）后换行
- 超过 100 字符时在最近的逗号处换行
- 无逗号则在第 100 个字符处硬换行

## 无损校验

每次清洗后自动校验：

1. 从清洗结果中移除所有插入的标点、换行、空格
2. 从源文中移除所有空格、制表符、换行、已有标点
3. 逐字比较两个字符串，必须完全一致

校验失败时不替换原始文件，报告首个差异位置和上下文。

## 推荐工作流

### 1. 确认范围

- 源文件或目录路径
- 输出位置（默认用测试目录如 `<source-parent>/直播转录标点测试/`）

### 2. 单文件试跑

先清洗一个代表性文件，让用户检查可读性：

```javascript
clean_asr({
  sourcePath: "<源文件路径>",
  outputPath: "<测试输出路径>"
})
```

### 3. 批量处理

用户确认试跑效果后，批量处理整个目录：

```javascript
clean_asr({
  sourcePath: "<源目录>",
  outputPath: "<输出目录>"
})
```

### 4. 校验

检查所有文件的校验报告，确认全部 PASS。如有 FAIL，检查首个差异位置。

### 5. 替换原始文件

所有文件校验通过后，将 `.md` 文件移动到源文件同目录（文件名仅扩展名改为 `.md`），删除原始 `.txt` 文件，随后清理 `.check.md` 临时文件。校验未通过的文件不得替换。

## 标点质量说明

脚本的标点插入是基于规则的，因此**不如人工精确**。例如：

- `吗` 总是触发 `？`，即使是用作修辞语气
- 某些语义停顿点可能被遗漏

但脚本**保证无损性**（100% 字符保留），这是人工/LLM 处理长文件时无法可靠达到的。

**推荐的混合工作流**：

1. 用脚本批量清洗 → 得到无损、标点合理的输出
2. 抽查可读性
3. 对个别需要改进的文件，手动调整脚本输出（不是源文件），然后用 `checkOnly: true` 重新校验
4. 全部校验通过后将 `.md` 移动到源目录并删除原始 `.txt`
