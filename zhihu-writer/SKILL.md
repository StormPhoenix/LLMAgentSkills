# zhihu-writer

知乎回答和文章生成器。专业回答、故事型回答、数据型回答、辩论型回答，以及专栏文章、爆款标题、盐选故事。

## 工具说明

本 Skill 提供 4 个工具，根据用户需求选择对应工具生成初始框架，再在框架基础上填充实际内容：

- `zhihu_answer` — 生成知乎回答框架，支持 professional / story / data / debate 四种风格
- `zhihu_article` — 生成知乎专栏文章框架
- `zhihu_title` — 生成 5 个爆款标题备选
- `zhihu_salt` — 生成知乎盐选付费故事开头

## 工作流程

1. **判断需求类型**：用户想写回答、文章、标题还是盐选故事
2. **选择风格**（仅 answer）：
   - 用户描述了具体问题类型 → 自动判断最合适的风格
   - 用户没有指定 → 默认 professional，或直接询问
3. **调用工具生成框架**：工具返回带占位符的 Markdown 结构
4. **基于框架填充内容**：结合用户提供的问题、主题、背景信息，将框架中的占位符替换为真实内容
5. **输出最终内容**：直接可发布到知乎平台的格式

## 风格选择指南

| 问题类型 | 推荐风格 |
|----------|----------|
| 技术/学习/职场专业类 | professional |
| 人生经历/情感/社会现象 | story |
| 经济/科技/社会议题（需要数据支撑） | data |
| 有争议的问题、想挑战主流观点 | debate |

## 写作质量要求

调用工具获得框架后，填充内容时必须遵守：

### 必须做到
- 开头第一句必须抓人，让读者产生"然后呢"的冲动
- 专业型和数据型回答：每个论点必须有具体案例或数据支撑，不能只有观点
- 故事型回答：细节要具体（时间、地点、人物、对话），不能泛泛而谈
- 辩论型回答：先承认对方合理之处，再提出反驳，不能上来就否定
- 长度控制在 1500-3000 字（知乎算法最优区间）
- 结尾必须有互动引导（点赞/评论/关注）

### 严禁
- 不得使用"首先…其次…最后"的套话结构
- 不得写"在当今社会""随着时代发展"这类空话开头
- 不得编造数据，如需数据支撑则标注"此处需补充真实数据"
- 不得无差别加粗，重要结论才加粗

## 知乎平台规则

- 每段不超过 3-4 行，保持阅读节奏
- 善用加粗、引用块（`>`）、分割线（`---`）
- 重要结论单独一段
- 回答热榜问题时效性极重要，24h 内回答权重最高
- 参考 `tips.md` 中的选题和涨粉技巧
- 参考 `examples.md` 中的高赞回答示例和写作要点

## 内容库保存（主动追问）

内容输出完毕后，主动询问是否保存：

```
📁 要把这篇保存到本地内容库吗？
  会保存到：桌面/我的内容库（勿动）/06-知乎写作/{{日期}}-{{关键词}}.md
  1. 保存（推荐）
  2. 不用
```

- 用户选"1" → 先用 `get_path` 获取桌面路径，再用 `write_text_file` 工具保存
- 用户模糊回答（"好""嗯""可以"）→ 按"1"处理
- **严禁**硬编码路径，必须通过 `get_path` 获取桌面路径

> 上述工具中：`get_path` 来自 core-tools Skill；`write_text_file` / `create_directory` 来自 file-write Skill。使用前需确保这两个 Skill 已启用。如果"我的内容库（勿动）/06-知乎写作"目录不存在，先用 `create_directory` 创建。
